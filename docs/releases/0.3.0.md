# Release v0.3.0 verification

The release pairs **Desktop 0.3.0** and **CLI 0.4.0**. Both package manifests
and lockfiles already carry these versions; downgrading the CLI is not required.
The earlier `desktop-v0.3.0` and `cli-v0.4.0` tags predate the full node work.
Keep those snapshots intact; the final umbrella `v0.3.0` tag must identify the
complete, verified release commit when publication is authorized.

The primary feature is installing and managing a personal Bitcoin full node
from CLI, Desktop and approved agent tools, including Mainnet and a local
explorer. Mainnet wallet spending remains a separate explicit opt-in. No
real-value transfer is part of the node acceptance checks.

## Artifacts and repeatable checks

```sh
npm run check
npm run test:desktop
npm run test:package
npm run dist:desktop
node scripts/node/package-check.mjs desktop/release/bitcode-desktop_0.3.0_amd64.deb
```

The release workflow performs the same checks on x64 and ARM64. Core staging
uses `scripts/node/verified-core.mjs`, which calls the node installer's actual
signature/hash verification and extraction function. The real Core smoke is
isolated from peers and existing chain data.

Host acceptance reports, package checksums and wizard screenshots belong in
`artifacts/fullnode/`; generated binaries belong in `desktop/release/`. Verify
the final `.deb`, rather than an earlier directory build, before publishing.

The locally checked amd64 Debian archive has SHA-256
`211c6eb86e7f66bfea834a68ef62834f3567e55cd53eb6cc8514409e941dd490`.

The 2026-10-26 CI failure on Node 22 was a CLI fixture race: it asserted output
after the child result appeared, before the parent's final answer. The check
now waits for the next input prompt before asserting the completed transcript.
