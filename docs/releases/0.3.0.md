# Release v0.3.0 verification

The release pairs **Desktop 0.3.0** and **CLI 0.4.0**. Both package manifests
and lockfiles already carry these versions; downgrading the CLI is not required.
The earlier `desktop-v0.3.0` and `cli-v0.4.0` tags predate the full node work.
Those snapshots remain intact; the umbrella `v0.3.0` release identifies the
complete, verified release commit. Final build provenance and checksums ship
as release assets.

The primary feature is installing and managing a personal Bitcoin full node
from CLI, Desktop and approved agent tools, including Mainnet and a local
explorer. Mainnet wallet spending remains a separate explicit opt-in. No
real-value transfer is part of the node acceptance checks.

## Host incident during final verification

After the successful adopted Mainnet acceptance, its project directory was
renamed externally from `FullNodeBTC - bitcode` to `FullNodeBTC - MAIN` while
Core was running. The user selected `FullNodeBTC - MAIN` as the permanent
path. Final verification found missing cookie and historical block reads, so
the adopted services were stopped. The corresponding regions in the canonical
block files were empty; the verified block and undo fragments pass Core framing
and checksum checks.
A complete backup of the affected configuration and block files is at
`/tmp/bitcode-mainnet-migration-20261027`.

The user applied the recovery with root authentication: the verified block
and undo records are restored, the project and systemd configuration point to
the selected path, and the Bitcode adoption record is updated. Reloading the
systemd manager and restarting Core subsequently completed. Full synchronization was
confirmed on 2026-10-29 and rechecked live on 2026-10-30, including both
Core indexes and the local explorer. The incident is resolved.

## Artifacts and repeatable checks

```sh
npm run check
npm run test:desktop
npm run test:package
npm run dist:desktop
node scripts/node/package-check.mjs desktop/release/bitcode-desktop_0.3.0_amd64.deb
```

The release workflow performs the same checks on x64 and ARM64. Core staging
uses `scripts/node/verified-core.mjs`, which calls the node installer's actual
signature/hash verification and extraction function. The real Core smoke is
isolated from peers and existing chain data.

Host acceptance reports, package checksums and wizard screenshots belong in
`artifacts/fullnode/`; generated binaries belong in `desktop/release/`. Verify
the final `.deb`, rather than an earlier directory build, before publishing.

the CLI npm archive, SHA-256 checksums and a provenance report identifying
the release commit and workflow runs. Earlier local packages and earlier
workflow artifacts are not the release assets.

The earlier `desktop-v0.3.0` and `cli-v0.4.0` tags remain intact. The umbrella
`v0.3.0` release identifies the integrated commit and pairs Desktop 0.3.0 with
